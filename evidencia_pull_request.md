# Evidencia Día 2 – Pull Request y Merge

## Objetivo
Demostrar el uso de Pull Request para integrar cambios en GitHub.

---

## Pasos realizados

### 1. Trabajo en una rama
Se trabajó en una rama diferente a la principal para realizar cambios sin afectar el proyecto base.

### 2. Subida de la rama
Los cambios se enviaron a GitHub desde la rama creada.

### 3. Creación del Pull Request
Desde GitHub se creó un Pull Request para comparar la rama secundaria con la rama principal.

### 4. Aprobación del Merge
El Pull Request fue aceptado, integrando los cambios a la rama principal.

---

## Resultado
Los cambios quedaron unidos correctamente en la rama principal del repositorio.
